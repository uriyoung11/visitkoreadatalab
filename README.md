> 방문객 수 하나로 성과를 판정하지 않습니다. 탐색·방문·숙박·체류·소비를 각각
> 확인하고, 지역별로 먼저 점검할 지점을 찾습니다.

## 네 지역의 핵심 결과

| 지역 | 관측된 흐름 | 우선 점검 축 |
|---|---|---|
| **완주 · 아원고택** | 방문은 늘었지만 숙박자 비율은 하락 | **숙박** |
| **순창 · 쉴랜드** | 방문은 2년 차에 회복했지만 소비는 낮은 수준 | **소비** |
| **완도 · 해양치유센터** | 체류는 길지만 방문자 대비 소비는 하락 | **소비** |
| **무주 · 태권도원** | 여러 지표가 개선됐지만 지정 전 상승 흐름이 함께 존재 | **체류 관찰** |

분석 결과는 관광지 자체 실적이 아니라 **시설이 위치한 시군구의 관광 흐름**입니다.
대조 지역이 없는 선정·지정 전후 분석이므로 인과효과로 단정하지 않습니다.

## 분석 기준

| 관측 축 | 지표 | 자료 |
|---|---|---|
| **탐색** | 숙박 목적지 검색 건수 | TMAP |
| **방문** | 외지인 방문자 수 | KT 이동통신 |
| **숙박** | 방문자 중 숙박자 비율 | KT 이동통신 |
| **체류** | 평균 체류시간 | KT 이동통신 |
| **소비** | 내국인 관광소비 | 신한카드 |

다섯 축은 동일 관광객의 이동 단계를 뜻하지 않습니다. 서로 다른 자료로 지역의
관광성과를 관측하는 독립 지표입니다.

- **분석 구간:** 지역별 선정·지정 발표월을 기준으로 이전 2년부터 이후 2년까지 P1–P4 구성
- **변화 확인:** 기간별 증감과 월별 구간회귀(ITS)를 함께 사용
- **보조 분석:** 소비 업종, 방문 출발지, 읍면동 분포, 주변 숙박 객실 공급
- **대상:** 완주·순창·완도는 2024년 신규 선정, 무주는 2022년 최초 지정 보강 사례

계산식과 해석 기준은 [분석 설계 문서](PROJECT.md)에 정리했습니다.

## 저장소 구성

```text
vercel-dashboard/                 Next.js 대시보드
scripts/                          분석·검증·웹 데이터 생성 코드
data/                             원자료와 88개 관광지 좌표 입력
output/4개_웰니스관광지_성과분석/  핵심 분석 결과
output/대시보드_보조데이터/        숙박 공급 등 보조 결과
```

`data/웰니스관광지_88개_좌표.csv`는 최종 보고서의 전국 88개소 좌표 기반 숙박 공급
분석을 재현하기 위한 입력입니다. 네 지역 대시보드만 실행할 때는 직접 사용하지 않지만,
보고서의 분석 근거이므로 저장소에 포함합니다.

## 실행

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python scripts/analyze_four_sites_by_designation.py
python scripts/analyze_four_site_lodging_supply.py
python scripts/build_vercel_dashboard_data.py

cd vercel-dashboard
npm ci
npm run build
```

Vercel 배포 시 Root Directory는 `vercel-dashboard`로 설정합니다.
